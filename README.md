# Magic Board · GitHub Pages

Google 로그인 후 비공개 Google Sheets를 읽는 개인용 대시보드입니다.

## 사용
- 게시된 GitHub Pages 주소를 열고, 시트 열람 권한이 있는 Google 계정으로 로그인합니다.
- 다른 컴퓨터나 휴대폰에서도 같은 주소와 계정으로 이용할 수 있습니다.
- 현재는 시트 소유 계정만 로그인 허용 목록에 있습니다. 계정을 추가하려면 Google Cloud 테스트 사용자와 시트 열람 권한을 둘 다 추가해야 합니다.
- 화면이 열려 있는 동안 약 60초마다 신규 기록을 확인합니다. 과거 기록도 주기적으로 다시 읽습니다.
- 로그인은 보통 약 1시간 후 만료됩니다. 데이터가 지워지면 다시 로그인하세요.
- 이 화면은 읽기 전용입니다. 메모·샵 설정 수정은 ‘편집 페이지’ 또는 ‘스프레드시트’에서 합니다. 즐겨찾기 핀만 이 브라우저에 저장됩니다.

## 수집은 별도
- 기존 Aside 수집이 KST 00:00, 12:00에 계속 시트에 기록합니다.
- GitHub는 수집하지 않으며, 시트나 데이터 파일을 공개하지 않습니다.
- 수집에는 기존 Mac, Aside, 로그인된 브라우저가 필요합니다.
- 00–12 / 12–24는 누적 판매의 관측 구간 차이입니다. 정확한 주문 시각이 아니며, 누락 구간을 추정하지 않습니다.

## 공개되는 것 / 비공개인 것
- 공개: HTML·JavaScript, Google OAuth 클라이언트 ID, 시트 ID, 편집 페이지 URL. 이 ID/URL은 비밀번호가 아니며 접근 권한을 주지 않습니다.
- 비공개: 실제 관측·메모·사용자 열, Google 접근 토큰, 계정 비밀번호.
- 접근 토큰과 조회 데이터는 현재 탭 메모리에만 유지하며, 로그아웃·만료 시 화면과 메모리 참조를 지웁니다. 토큰이나 데이터를 브라우저 저장소·GitHub에 저장하지 않습니다.
- 요청 범위는 Google Sheets 읽기 전용입니다. 클라이언트 시크릿·서비스 계정 키·API 키는 사용하지 않습니다.
- 저장소에 실제 시트 데이터, 수집 실행 파일, 인증 JSON, 스크린샷을 업로드하지 마세요.

## 재배포 설정
1. Google Cloud에서 Google Sheets API를 켭니다.
2. Google Auth Platform에서 외부/테스트 앱을 구성하고 시트 소유 계정을 테스트 사용자로 추가합니다.
3. 웹 애플리케이션 OAuth 클라이언트를 만들고 게시 사이트의 HTTPS origin을 승인합니다. 경로 없이 origin만 입력합니다.
4. `config.js`의 공개 클라이언트 ID와 시트 ID를 설정합니다. 시크릿은 넣지 않습니다.
5. 이 폴더의 배포 파일을 저장소 루트에 올리고 Pages를 main 브랜치 / (root)에서 게시합니다.
6. HTML 파일을 직접 열지 말고 게시 주소를 사용합니다. 복사한 다른 도메인은 OAuth 승인 origin도 갱신해야 합니다.

Google 계정·시트 공유 설정은 그대로 유지하세요. 개인정보 안내는 [privacy.html](privacy.html)을 확인하세요.
